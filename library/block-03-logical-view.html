Block 3: Logical view

Block 3 of the Microsoft Purview deep dive - logical view.

Time: 60 minutes · Goal: Components, data entities, and logical flows, vendor-neutral

Work in: Logical View

Focus from mind map

  • Assume no prior knowledge: what Purview is, and what it is not (vs Defender, Entra, Sentinel)
  • Conceptual view (block 2)
  • Logical view (block 3)
  • eDiscovery: cases, holds, search, review, export
  • Physical view (block 4)
  • Portals, services, agents, and scanners that realize each logical component

Sources

Actions

  • Decompose each capability into logical components with responsibilities.
  • Build the logical data model (entities, relationships, classification).
  • Draw the main logical flows; mark each sync or async.

Retrieval check

Question

Which logical component realizes the main capability, and what data entity does it own?

Answer cues

Classification engine realizes C1; its input/output entity is Content, scan results.

Exit criteria

  • Every capability has at least one logical component; data model drawn.
