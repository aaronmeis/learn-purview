Block 6: Hands-on lab

Block 6 of the Microsoft Purview deep dive - hands-on lab.

Time: 60 minutes · Goal: Configure or trace one real end-to-end flow

Focus from mind map

  • Context and boundary (block 1)
  • Conceptual view (block 2)
  • Capabilities: know your data · protect it · prevent loss · manage insider risk · respond and investigate · govern data estate · manage compliance posture · secure AI use
  • Classification: sensitive information types, trainable classifiers
  • Information Protection: sensitivity labels and label policies
  • Data Loss Prevention: policies, locations, actions
  • Audit: unified audit log, retention of audit records
  • Compliance Manager: assessments, improvement actions, score
  • Portals, services, agents, and scanners that realize each logical component

Sources

  • Learn about Microsoft Purview (solution families)
  • Data sources that connect to Purview Data Map (capability matrix)
  • Choose the right integration runtime (IR matrix per source)
  • Feature availability for Microsoft Purview (Azure Government exclusions)
  • Plan for Microsoft Purview - GCC deployments
  • Plan for Microsoft Purview - GCC High deployments
  • Plan for Microsoft Purview - DoD deployments
  • Cloud feature availability for US Government customers

Actions

  • Pick one end-to-end flow and configure it or trace it in a tenant, trial, or docs walkthrough.
  • Capture screenshots or config snippets as evidence under assets/.
  • Note every place the docs and the product disagree.

Retrieval check

Question

What did the lab show that the documentation did not?

Answer cues

Expected before running it: One end-to-end flow, chosen after the views are drafted (candidate: label → DLP → audit trail on SharePoint content). This is the one answer research alone can't give — record what actually happened here after the lab.

Exit criteria

  • One flow configured or traced with evidence saved.
