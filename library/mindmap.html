Drafted from the 2026-09-26 technical interview. Branches are the scope you named, not researched claims. Edit freely, then give GO.

Source rule (your falsifier)

Only Microsoft-grounded sources: Microsoft Learn (Purview, Microsoft 365 and Azure Government docs), the Azure Architecture Center and Microsoft reference architectures, Microsoft Tech Community, and Microsoft-owned video (Microsoft Mechanics, Ignite, Build). Every use case must trace to a Microsoft reference architecture. Third-party vendor docs are allowed only to confirm the far side of a connector, and they are labeled as such. Anything else is marked UNVERIFIED and kept out of the views.

Microsoft Purview

  • Context and boundary (block 1)
  • Assume no prior knowledge: what Purview is, and what it is not (vs Defender, Entra, Sentinel)
  • Two halves: Microsoft 365 data security and compliance · data governance (Data Map, Data Catalog)
  • Clouds: Commercial (global), GCC, GCC High, DoD, Azure Government. No Secret or Top Secret, no air gap.
  • Conceptual view (block 2)
  • Capabilities: know your data · protect it · prevent loss · manage insider risk · respond and investigate · govern data estate · manage compliance posture · secure AI use
  • Actors: compliance admin, security analyst, data owner and steward, investigator, end user, auditor
  • Logical view (block 3)
  • Classification: sensitive information types, trainable classifiers
  • Information Protection: sensitivity labels and label policies
  • Data Loss Prevention: policies, locations, actions
  • Insider Risk Management: indicators, policies, alerts and cases
  • eDiscovery: cases, holds, search, review, export
  • Audit: unified audit log, retention of audit records
  • Data Map and Data Catalog: sources, scans, assets, lineage, glossary
  • Compliance Manager: assessments, improvement actions, score
  • DSPM for AI: discovery of AI use, policies, reports
  • Physical view (block 4)
  • Portals, services, agents, and scanners that realize each logical component
  • Licensing tiers per capability
  • Cloud variants table: which capabilities exist in Commercial, GCC, GCC High, DoD, Azure Government
  • Integration (block 5)
  • Third-party and external: AWS · Snowflake · Salesforce · on-prem file shares · OneTrust
  • First-party target: SharePoint
  • Per system: direction, mechanism, data exchanged, auth, gov-cloud support
  • AI elements (block 5)
  • AI fundamentals for models and agents, as Purview governs them
  • DSPM for AI
  • AI interaction logging: audit and retention of Copilot and AI interactions
  • AI data path: prompt → grounding data → label, DLP, and access checks → response → log
  • Hands-on lab (block 6, real tenant)
  • One end-to-end flow, chosen after the views are drafted (candidate: label → DLP → audit trail on SharePoint content)
  • Failure modes and security (block 7)
  • Per view: misconfiguration, licensing gaps, gov-cloud feature gaps, connector breakage, AI oversharing
  • Design review (block 8)
  • Defend the views against the Microsoft reference architectures used as sources
