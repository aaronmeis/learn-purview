Altitude rule

Conceptual means what and why, not how. Capabilities and actors only. Product names appear here only where Microsoft uses them as the capability name.

Problem and purpose

Microsoft states the problem as four pressures: data fragmented across the organization, a lack of visibility that hampers protection and governance, fast AI adoption, and blurred IT management roles [S1]. Purview is Microsoft's answer: one platform to govern, protect, and manage data wherever it lives [S1].

Capabilities

Microsoft's five stated outcomes, used here as the top-level capability map [S1]:

# Capability Outcome it delivers Actors Source
C1 Know your data Visibility into data across the organization Data owner, steward, compliance admin [S1]
C2 Protect sensitive data Safeguard and manage sensitive data across its lifecycle, wherever it lives Compliance admin, end user [S1]
C3 Govern data Catalog, classify, and curate the data estate Data steward, data source admin [S1], [S2]
C4 Manage risk and regulation Manage critical data risks and regulatory requirements Compliance admin, investigator, auditor [S1]
C5 Secure AI use Prevent oversharing and sensitive data leakage in generative AI Security and compliance analyst [S1], [S15]

Solution families (how Microsoft groups the capabilities)

Family What it answers Solutions in scope for this deep dive Source
Data security Is sensitive data protected and not leaking? Information Protection, Data Loss Prevention, Insider Risk Management, DSPM [S1]
Data governance What data do we have, where, and who owns it? Data Map, Unified Catalog [S1]
Data compliance Can we prove and enforce obligations? Audit, eDiscovery, Compliance Manager (also Data Lifecycle Management, Communication Compliance, Records Management) [S1]
AI protections Is AI use safe and auditable? DSPM for AI, AI interaction auditing [S1], [S15]

Shared across families: classifiers, connectors, data explorer and activity explorer, sensitivity labels [S1].

Actors

Actor Role Goal Source
Compliance administrator Configures policies and DSPM for AI Policy coverage [S18]
Security and compliance analyst Triages DLP and insider risk alerts Act on real risk [S30]
Data source admin / data reader Registers and scans sources in the Data Map Complete catalog [S10], [S11]
Investigator Runs eDiscovery cases and audit searches Evidence [S16]
End user Labels and handles content, uses Copilot and agents Work safely [S16]
Agent (non-human) Reads and writes data on a user's behalf Governed like its parent app [S17]

Key concepts

Concept Meaning Source
Classification Detecting sensitive information types with classifiers [S1]
Sensitivity label Persistent marking that can carry protection [S1]
Policy Rule that acts on classified or labeled data (DLP, retention, insider risk) [S1]
Data estate All sources the Data Map knows about, including non-Microsoft ones [S2]
AI interaction A prompt and response between a user or agent and an AI app [S16]
