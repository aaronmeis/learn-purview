Block 7: Failure modes and security

Block 7 of the Microsoft Purview deep dive - failure modes and security.

Time: 45 minutes · Goal: What breaks, what leaks, and what the controls actually stop

Focus from mind map

  • Context and boundary (block 1)
  • Assume no prior knowledge: what Purview is, and what it is not (vs Defender, Entra, Sentinel)
  • Two halves: Microsoft 365 data security and compliance · data governance (Data Map, Data Catalog)
  • Capabilities: know your data · protect it · prevent loss · manage insider risk · respond and investigate · govern data estate · manage compliance posture · secure AI use
  • Actors: compliance admin, security analyst, data owner and steward, investigator, end user, auditor
  • Information Protection: sensitivity labels and label policies
  • Insider Risk Management: indicators, policies, alerts and cases
  • Data Map and Data Catalog: sources, scans, assets, lineage, glossary
  • Portals, services, agents, and scanners that realize each logical component

Sources

  • Learn about Microsoft Purview (solution families)
  • Data sources that connect to Purview Data Map (capability matrix)
  • Choose the right integration runtime (IR matrix per source)
  • Feature availability for Microsoft Purview (Azure Government exclusions)
  • Plan for Microsoft Purview - GCC deployments
  • Plan for Microsoft Purview - GCC High deployments
  • Plan for Microsoft Purview - DoD deployments
  • Cloud feature availability for US Government customers

Actions

  • List the top failure modes per view (conceptual, logical, physical, integration).
  • For each, name the tell and the control that should catch it.
  • Include AI oversharing and third-party connector failure.

Retrieval check

Question

What is the most likely failure in a real Microsoft Purview deployment, and what is its first visible tell?

Answer cues

Leading candidate: S3 scanning unavailable in Azure Government Data Map; mitigate via Scan S3 from a commercial Purview account, or accept the gap; design decision for block 8.

Exit criteria

  • Failure-mode table covers all four views.
