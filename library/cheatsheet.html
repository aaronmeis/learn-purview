Cheatsheet — Microsoft Purview

Decision rules and tells.

Decision rules only.

Scope and capability

  • When you need to know "what data do we have and where," reach for Data Map + Unified Catalog (C1/C3), not DLP — DLP acts on data you've already classified, it doesn't discover it [S1], [S2].
  • When the ask is "stop this AI app from oversharing," the answer is always clean permissions + labels first, DSPM for AI second — DSPM discovers and assesses, it doesn't retroactively fix bad ACLs [S15].
  • When a request spans multiple solution families (e.g. "govern AND protect AND prove compliance"), name the family split explicitly — Purview is one portal but four separable products (data security / data governance / data compliance / AI protections) with different licenses [S1], [S25].

Scanning and connectors

  • When scanning Amazon S3 or RDS, remember Purview only reaches them via an AWS-hosted IR that Microsoft itself operates in its own AWS account — you are not standing up your own runtime for these [S3], [S9].
  • When scanning on-prem file shares, SQL, or SharePoint Server, you need a self-hosted IR or the information protection scanner running on customer-owned Windows Server — that's the only place customer infrastructure actually appears in the topology [S12], [S13].
  • When a connector returns data to Purview, default assumption is metadata and classification only, never content — confirmed explicitly for the S3 connector [S9] and implied by the Data Map's whole design [S2].
  • When Snowflake auth breaks, check for basic auth — Snowflake is retiring it in 2026; move to key pair (RSA, PKCS#8) and store the private key via Azure CLI, not the portal (the portal corrupts multi-line PEM) [S10].
  • When Salesforce scanning is incomplete, remember it returns technical metadata only — no classification runs on Salesforce objects/fields, unlike S3 or Snowflake [S2], [S11].

Gov-cloud and licensing

  • When a design needs S3 or RDS scanning AND Azure Government, that's a hard incompatibility — the Data Map explicitly excludes S3, RDS, and commercial Power BI in Azure Government (Power BI GCC is fine) [S4]. Scan from a commercial Purview account instead, or accept the gap.
  • When someone claims "GCC is FedRAMP Moderate" and someone else claims "GCC is FedRAMP High," both are right — GCC's formal P-ATO is Moderate, but Microsoft has separately passed FedRAMP High audits and claims High "Equivalency." Don't treat this as a documentation error [S35].
  • When comparing GCC / GCC High / DoD feature tables, remember "Baseline" = commercial — the gov-cloud service descriptions only list differences from commercial, so a blank cell usually means parity, not absence [S7].
  • When DSPM for AI is needed in GCC High or DoD, know the specific limit: no browse-to-URL policy creation, and only a supported subset of AI sites [S7].
  • When scoping licenses, remember every user who touches a scanned on-prem location needs a license, not just the scanner service account — this is a common under-licensing trap [S14].

AI data path

  • When asked "what stops Copilot from leaking a file the user can't open," the answer is the query-time permission/label/DLP check between grounding and response — not a one-time index-build check [conceptually shown in the AI data path diagram, S15]/[S16].
  • When investigating a Copilot interaction, remember the Audit solution only stores a transcript thread ID for Copilot Studio — DSPM for AI's activity explorer is what actually retrieves the chat text, not raw Audit search [S21].
  • When prompts/responses seem to be "missing" from an investigation, check whether a collection policy is turned on — without it, Fabric/Security Copilot/non-Copilot AI apps only emit audit events, not prompt/response text [S15].
  • When comparing agent platforms, know the support matrix has a hard exclusion list: ChatGPT Enterprise and Claude Enterprise agents are not supported by Purview's agent protections [S17].

Architecture placement

  • When deciding where the Purview account itself lives, it's an Azure resource (Data Map + Unified Catalog), not a Microsoft 365 tenant resource — Microsoft recommends one dedicated data-management landing zone per Entra tenant [S24].
  • When mapping the 4-cloud topology, the pattern is: M365 tenant = admin portal + compliance solutions + unified audit log; Azure subscription = Purview account + Key Vault + Managed VNet IR; AWS = Microsoft-hosted IR only, for S3; customer estate = self-hosted IR, scanner, file shares, onboarded devices — nothing else runs on customer infrastructure [diagram, view 03].
  • When network security is in scope, Purview account isolation is via Azure Private Link, not a firewall allowlist alone [S23].

Falsifier

  • "Purview intercepts the retrieval" is imprecise — sources describe agents as inheriting their parent app's protections (labels, DLP), not Purview sitting inline as a proxy. Narrate it as inheritance, not interception.
