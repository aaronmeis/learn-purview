Microsoft Purview Technical Study Guide

Section 1: Architecture & Capability Overview

1. Conceptual Architecture & Platform Context

Microsoft Purview is an integrated platform designed to govern, protect, and manage data assets across on-premises, multicloud, and Software-as-a-Service (SaaS) environments. The platform addresses four major enterprise pressures: 1. Data fragmentation across hybrid and multicloud ecosystems. 2. Lack of visibility, which hinders governance and data protection. 3. Rapid adoption of generative AI and agentic workflows. 4. Blurred boundaries between operational IT, security, and compliance management roles.

Core Solution Families & Stated Outcomes

Solution Family Strategic Focus Area Core Solutions In Scope Key Stakeholders
Data Security Preventing data leakage, protecting sensitive content, managing insider threats, and establishing data security posture. Information Protection, Data Loss Prevention (DLP), Insider Risk Management (IRM), Data Security Posture Management (DSPM). Compliance Administrator, Security Analyst, End User.
Data Governance Cataloging, searching, classifying, and tracing lineage across the enterprise data estate. Data Map, Unified Catalog. Data Owner, Data Steward, Data Source Admin.
Data Compliance Demonstrating regulatory alignment, enforcing retention policies, and managing legal content discovery. Audit, eDiscovery, Compliance Manager, Data Lifecycle Management (DLM), Communication Compliance, Records Management. Compliance Admin, Investigator, Auditor.
AI Protections Discovering AI usage, enforcing guardrails, auditing interactions, and preventing AI oversharing. DSPM for AI, AI Interaction Auditing, Collection Policies. Security Analyst, AI System Owner, Compliance Admin.

Platform Actors & Roles

  • Compliance Administrator: Configures organizational policies, DLP rules, label policies, and DSPM guardrails.
  • Security & Compliance Analyst: Triages incoming alerts from DLP and Insider Risk Management; reviews DSPM risk reports.
  • Data Source Admin / Data Reader: Registers data sources, configures scanning credentials, and executes Data Map scans.
  • Investigator: Executes eDiscovery searches, sets legal holds, and reviews Unified Audit Log entries.
  • End User: Applies sensitivity labels, consumes classified data, and interacts with Microsoft Copilot and AI agents.
  • Non-Human Agent: Executes autonomous or semi-autonomous data operations on behalf of a user, inheriting parent application permissions and governance guardrails.

Logical Components & Responsibilities

Logical Component Core Responsibility Primary Inputs Primary Outputs
Classification Engine Evaluates content against Sensitive Information Types (SITs) and trainable classifiers. Unstructured/structured content, scan payloads. Content classifications, matched SIT metadata.
Information Protection Applies persistent metadata markings (sensitivity labels) and cryptographic protection. Classification signals, label policies. Labeled content, encrypted files/emails.
Data Loss Prevention (DLP) Detects and restricts unauthorized handling, transmission, or exfiltration of sensitive data. Activity signals, DLP policies, label state. Real-time policy actions (block, warn, audit), alerts.
Insider Risk Management Correlates cross-workload behavioral signals to identify potential user-driven risks. HR signals, audit log events, AI interactions. Risk alerts, investigator case files.
Data Map Discovers, scans, classifies, and traces technical metadata and lineage across registered sources. Source credentials, endpoint schemas. Asset metadata, lineage maps, classification graphs.
Unified Catalog Exposes curated data assets, business glossary terms, and ownership details for consumption. Data Map assets, steward annotations. Curated data asset catalog, glossary mappings.
Audit Ingests and maintains immutable event logs for user, administrator, and AI agent activities. Workload activity feeds, Copilot interactions. Queryable Unified Audit Log records.
eDiscovery Manages legal cases, executes search queries across workloads, places legal holds, and exports content. Search queries, target mailboxes/sites/chats. Legal holds, review sets, exported evidence files.
Compliance Manager Tracks organizational compliance posture against regulatory baselines (e.g., NIST, GDPR). Tenant configuration state, manual evidence. Compliance score, prioritized improvement actions.
DSPM for AI Analyzes AI usage, detects sensitive data in AI prompts/responses, and identifies data oversharing. Copilot interaction logs, SharePoint permissions. AI risk assessments, automated remediation policies.

Logical Data Entities

  • Sensitivity Label: Represents content classification state and protection settings (encryption, visual markings, access rights).
  • Sensitive Information Type (SIT): Pattern-based rules (regex, checksums, keywords) or machine-learning models used to detect specific data forms (e.g., credit card numbers, national IDs).
  • Policy: Administrative construct mapping conditions and locations to specific actions (e.g., DLP block, retention rule, IRM indicator).
  • Data Source: External or internal repository containing enterprise data assets.
  • Asset: Granular object within a Data Source (e.g., table, view, blob, file) containing schemas, classifications, and lineage links.
  • Audit Record: Structured log entry containing timestamp, actor identity, workload origin, and operation details (e.g., CopilotInteraction).
  • AI Interaction: A pairing of prompt text, generated response, invocation context, referenced files, and agent identities.
  • Case: Administrative workspace aggregating legal holds, search criteria, review sets, or insider risk alerts.

Key Logical Data Flows

  1. F1 (Metadata Scan): Data Source $\rightarrow$ Data Map. Transmits technical metadata, schemas, and classification findings. Content payload is never returned or stored in the Data Map.
  2. F2 (On-Prem Labeling): Scanner $\rightarrow$ Local File Share. Evaluates local files over SMB/NFS and writes persistent sensitivity label metadata directly to the file header.
  3. F3 (DLP Evaluation): User/System Action $\rightarrow$ DLP Engine. Evaluates real-time operation against active DLP policies to permit, warn, audit, or block the transaction.
  4. F4 (AI Interaction Audit): AI App / Copilot $\rightarrow$ Unified Audit Log. Emits structured CopilotInteraction telemetry containing interaction context and referenced content metadata.
  5. F5 (AI Risk Analysis): Unified Audit Log $\rightarrow$ DSPM for AI. Ingests interaction telemetry to generate activity explorer views, oversharing assessments, and risk analytics.
  6. F6 (eDiscovery / Retention): AI Interactions $\rightarrow$ Data Lifecycle Management / eDiscovery. Retains, holds, or exports interaction records matching specified retention policies or legal case filters.

Integration Runtimes (IR) Matrix

Integration Runtime Type Hosting Infrastructure Target Use Cases Maintenance Responsibility Network Access Requirements
Azure IR Fully managed by Microsoft. Publicly accessible cloud endpoints (Azure Blob, Azure SQL, Salesforce). Fully automated by Microsoft. Public internet endpoints or trusted Azure service access.
Managed VNet IR Hosted in a Purview-managed virtual network. Private endpoints into Azure PaaS resources without agent deployment. Fully automated by Microsoft. Azure Private Endpoints; supports Managed Private Endpoints (v1/v2).
Self-Hosted IR (SHIR) Customer-managed Virtual Machine or physical server. On-premises networks, private cloud VNets, isolated databases (e.g., Oracle, DB2). Customer manages OS, Java JDK 11 runtime, patching, and updates. Outbound HTTPS (port 443) to Microsoft Purview control plane.
Kubernetes SHIR Host cluster running inside customer Kubernetes infrastructure. High-throughput, auto-scaling, containerized scanning jobs. Customer manages Kubernetes cluster; manual IR software updates. Outbound network access to Purview service endpoints.
AWS IR Fully managed by Purview inside a dedicated AWS account. AWS native data sources (Amazon S3 buckets, Amazon RDS). Fully automated by Microsoft. Cross-account AWS IAM Role Assumption with External ID.

Operational Note on Hibernation: Managed Virtual Network IRs enter hibernation after 90 days of inactivity. Executing a connection test or manual scan wakes the IR, transitioning the status to Queued_Waking Up IR. Wake-up takes up to 15 minutes.

Generative AI Control Capabilities

AI Control Feature Functional Role Data Monitored / Processed Key Dependency / Governance Rule
DSPM for AI Centralized dashboard for tracking enterprise AI app usage, agent activity, and risk metrics. Prompts, responses, user risk levels, referenced SharePoint sites. Requires activity logging (enabled by default for M365 Copilot and Azure AI).

Section 2: Practice Short-Answer Questions & Answer Key

Practice Questions

  1. What primary architectural problem does Microsoft Purview address across modern enterprise data environments?
  2. How do the Data Map and Data Catalog differ in their architectural scope and primary operational outputs?
  3. What is the fundamental data boundary rule when scanning third-party cloud data stores like Amazon S3 using the Multicloud Scanning Connector?
  4. What physical hosting requirement applies to the operating system when deploying the on-premises Information Protection Scanner?
  5. Why does a Managed Virtual Network Integration Runtime (IR) exhibit a 15-minute delay when executing a scan after prolonged inactivity?
  6. What identity pairing distinction exists between Microsoft 365 GCC deployments and GCC High / DoD deployments?
  7. What critical governance artifact must be configured to ensure full prompt and response text is captured during eDiscovery investigations for Microsoft Security Copilot or Copilot in Fabric?
  8. How does Microsoft Purview handle agentic security when a user interacts with a custom AI agent built in Copilot Studio?
  9. What authentication constraint and portal deployment trap exists when configuring Purview Data Map connectors for Snowflake?
  10. What scanning capability gap exists for Microsoft Purview Data Map when operating specifically within an Azure Government cloud environment?

Answer Key

  1. Microsoft Purview addresses the governance and protection challenges caused by fragmented data estates, lack of structural visibility, accelerated AI adoption, and blurred boundaries between security, compliance, and IT management roles. It unifies data governance, security posture management, compliance auditing, and AI guardrails under a single operational framework across hybrid and multicloud ecosystems.
  2. The Data Map operates as the back-end engineering engine that discovers, scans, classifies, and maps lineage for raw assets across registered data sources. The Data Catalog sits on top of the Data Map as the front-end curation layer, allowing business users and stewards to search, annotate, and manage business glossary terms and asset ownership.
  3. The Multicloud Scanning Connector extracts and transmits only technical metadata, asset schemas, and classification findings back to Microsoft Purview. Actual raw file contents and underlying data payloads are never returned to, stored in, or transmitted across the Purview cloud boundary during AWS S3 scans.
  4. The Information Protection Scanner must be installed on a dedicated 64-bit instance of Windows Server (2016, 2019, 2022, or 2025). The installation explicitly forbids the use of stripped-down Windows installation variants, specifically Server Core and Nano Server.
  5. Managed Virtual Network IRs automatically enter a hibernated state after remaining idle for more than 90 days to conserve compute resources. Waking up a hibernated runtime requires up to 15 minutes to re-provision the underlying managed virtual network infrastructure, during which time the job queue displays Queued_Waking Up IR.
  6. Microsoft 365 GCC environments pair their identity tier with commercial Microsoft Entra ID in global Azure. In contrast, GCC High and DoD deployment tiers pair exclusively with Microsoft Entra ID instances hosted within the physically isolated Azure Government cloud infrastructure.
  7. Administrators must explicitly configure a Purview Collection Policy targeting those specific AI workloads. Without an active collection policy, the platform records standard CopilotInteraction audit log events but completely omits the underlying prompt and response text payloads required for deep forensic review.
  8. Custom AI agents inherit the underlying access permissions, classification rules, and DLP controls of the invoking user and parent application. Additionally, DSPM for AI actively flags risk indicators such as unauthenticated user access, overly permissive grounding site permissions, or agents exposed directly to internet users.
  9. Snowflake connectivity relies on RSA Key Pair authentication in PKCS#8 format, as Snowflake is retiring basic authentication in 2026. Administrators must upload private keys using Azure CLI scripts because pasting multi-line PEM strings directly into the Purview management portal corrupts line-break formatting.
  10. The Multicloud Scanning Connector for Amazon S3 is not supported in Azure Government Data Map instances. Furthermore, Azure Government Data Map excludes preview data sources, Amazon RDS, commercial Power BI scans, and Synapse pipeline lineage tracking.

Section 4: Key Terms Glossary

  • Agent (Non-Human): An autonomous or semi-autonomous software entity (e.g., created via Copilot Studio or Azure AI Foundry) that executes tasks, queries data sources, and generates responses on behalf of a user while operating under inherited governance controls.
  • Amazon S3 Multicloud Scanning Connector: A specialized Purview integration framework utilizing AWS IAM role assumption to extract metadata and run classification algorithms over unstructured files in Amazon S3 buckets without transferring actual object content to Azure.
  • Asset: A specific, granular data entity registered within the Purview Data Map—such as a database table, SQL view, blob container, or file—that contains technical schemas, annotations, and classification metadata.
  • Azure Integration Runtime (Azure IR): A fully managed, elastic compute runtime deployed by default in Microsoft Azure used to scan cloud data sources with publicly accessible endpoints.
  • Classification Engine: The logical Purview component that analyzes structured and unstructured content against pattern matching definitions (SITs) or trained machine-learning models to determine data sensitivity.
  • Collection Policy: An administrative rule in Microsoft Purview required to capture full prompt and response text payloads for advanced Copilot workloads (e.g., Fabric Copilot, Security Copilot) and store them for compliance auditing and eDiscovery.
  • Compliance Manager: An end-to-end risk and posture assessment solution within Purview that continuously measures tenant configurations against regulatory frameworks (e.g., NIST, ISO, GDPR) to calculate an enterprise Compliance Score.
  • CopilotInteraction: The standardized schema format used within the Microsoft 365 Unified Audit Log to record interaction events between users, agents, and Microsoft Copilot instances.
  • Data Landing Zone (DLZ): An Azure architectural boundary (comprising one or more subscriptions) within the Cloud Adoption Framework dedicated to hosting analytical engines, data products, and platforms like Azure Databricks or Data Lake Storage.
  • Data Management Landing Zone (DMLZ): A subscription boundary within the Azure Cloud Adoption Framework dedicated to hosting centralized governance assets, specifically the organization's primary Microsoft Purview account and Microsoft Fabric shared compute capacities.
  • Data Map: The core automated cataloging and metadata engine of Purview that scans, classifies, indexes, and draws lineage maps across hybrid, on-premises, and multicloud data sources.
  • Data Security Posture Management (DSPM) for AI: A dedicated Purview solution designed to discover AI application usage, identify data oversharing vulnerabilities, detect sensitive data in prompts/responses, and enforce automated security guardrails across AI interactions.
  • Double Key Encryption (DKE): An advanced protection mechanism within Microsoft Purview Information Protection that utilizes two cryptographic keys—one stored safely in Microsoft Azure and one controlled exclusively by the customer—to protect highly sensitive content.
  • eDiscovery (Premium): An end-to-end legal workflow solution in Purview that provides custodial management, deep content searching, legal holds, in-place review sets, redacting, and data export capabilities for litigation support.
  • Information Protection Scanner: A Windows Server background service deployed on-premises to discover, classify, label, and protect files stored on SMB file shares, NFS shares (preview), and local SharePoint Server document libraries.
  • Insider Risk Management (IRM): A data security solution that correlates activity signals across Microsoft 365 workloads, HR systems, and AI interactions to identify, triage, and investigate potential risky user behaviors (e.g., IP theft by departing employees).
  • Integration Runtime (IR): The underlying compute infrastructure that powers Microsoft Purview Data Map scans across varied network topographies and cloud environments.
  • Know Your Data (KYD) Policy: A specialized configuration policy created via Microsoft Graph APIs and the Purview SDK that enables DSPM controls, sensitive data detection, and interaction monitoring for custom enterprise AI applications.
  • Managed Virtual Network Integration Runtime: A managed scanning runtime hosted inside a isolated Purview virtual network that leverages private endpoints to securely scan data stores without exposing traffic to the public internet.
  • OneLake: The single, unified, logical data lake provided by Microsoft Fabric that acts as an enterprise-wide aggregation layer for analytical and operational data storage.
  • OneTrust Connector: A third-party security integration that ingests sensitive data findings from OneTrust scans into Microsoft Purview DSPM via Microsoft Sentinel.
  • Restrict Access by Label: A granular governance setting that restricts Microsoft Copilot and AI agents from reading or summarizing content assigned specific high-sensitivity labels, even if the invoking user possesses underlying read permissions to the source file.
  • Self-Hosted Integration Runtime (SHIR): Customer-managed software installed on an on-premises physical machine, virtual machine, or Kubernetes cluster used to execute scans against isolated on-premises or private network data sources.
  • Sensitive Information Type (SIT): A pattern-based data classification definition utilizing regular expressions, character proximity, alphanumeric checksums, or keyword dictionaries to detect specific sensitive formats (e.g., credit card numbers, tax IDs).
  • Sensitivity Label: A persistent metadata tag applied to files, emails, or containers that enforces visual markings, access control restrictions, and cryptographic protection across the content lifecycle.
  • Trainable Classifier: A machine-learning model trained on sample document vectors to classify complex, non-standardized unstructured content based on intent and contextual structure (e.g., legal agreements, financial contracts).
  • Unified Audit Log (UAL): A centralized, immutable audit repository across Microsoft 365 that records user, system, administrative, and AI interaction events for operational reporting, forensic analysis, and security investigations.
  • Unified Catalog: The business-facing discovery portal built on the Data Map that enables data consumers, stewards, and analysts to search assets, inspect schemas, trace lineage, and manage business glossary definitions.
