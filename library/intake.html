Scope interview

Technical interview — Microsoft Purview

scope

Which part of the platform is in scope, and what is explicitly out? Name the sub-products.

Answer:

All of Purview: Information Protection and sensitivity labels, Data Loss Prevention, Insider Risk Management, eDiscovery, Audit, Data Map and Data Catalog (data governance), Compliance Manager, and DSPM for AI.

tenant_cloud

Which cloud and tenant type: commercial, GCC, GCC High, DoD, Azure Government Secret/Top Secret? Any air gap?

Answer:

Commercial (global), GCC, GCC High, DoD, and Azure Government. No Secret or Top Secret clouds for now. No air gaps.

prior_knowledge

What do you already know about this platform and its neighbors? What is brand new?

Answer:

Assume no prior knowledge of Purview.

integrations

Which integrations matter: third-party and external systems (SIEM, ITSM, other clouds, SaaS, on-prem), APIs, identity providers?

Answer:

AWS, Snowflake, Salesforce, on-prem file shares, OneTrust (third-party and external). SharePoint (first-party Microsoft 365, in scope as an integration target).

ai_features

Which AI features or AI data paths are in scope (copilots, AI governance, model data flows)?

Answer:

DSPM for AI, AI interaction logging (audit and retention of Copilot/AI interactions), and AI fundamentals for models and agents as Purview governs them.

lab_access

What can you touch hands-on today: a tenant, a trial, a sandbox, or docs only?

Answer:

Real tenant.

falsifiers

What would make this deep dive a waste (wrong altitude, marketing depth, wrong cloud)?

Answer:

Any information that is not validated and grounded in Microsoft or Purview sources. Every use case must be traceable to Microsoft reference architectures.
