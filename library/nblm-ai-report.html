Technical Report: Microsoft Purview AI Capabilities, Governance Architecture, and Integration Surface

1. Executive Architecture Overview & Platform Scope

Microsoft Purview functions as a unified enterprise data security, compliance, and governance platform engineered to establish comprehensive visibility and control across on-premises, multicloud, and Software-as-a-Service (SaaS) environments. The widespread and rapid adoption of Generative AI (GenAI)—characterized by an estimated 78% of enterprise employees bringing consumer-grade AI tools into their workflows—presents unprecedented data protection challenges. These challenges include unmanaged Shadow AI adoption, sensitive data exfiltration via prompt inputs, unauthorized data oversharing through pervasively accessible content repositories, and the rapid proliferation of autonomous or maker-created AI agents. Purview addresses these risks by extending its foundational data security mechanism—encompassing classification engines, sensitivity labeling, Data Loss Prevention (DLP), and Information Rights Management (IRM)—directly into real-time AI grounding paths, agent execution frameworks, and custom LLM applications.

The platform architecture bridges two distinct operational disciplines: Microsoft 365 Data Security and Compliance (focusing on Information Protection, DLP, Insider Risk Management, Audit, and eDiscovery) and Azure Data Governance (centered on the Data Map and Unified Catalog). When applied to GenAI workloads, Purview establishes a centralized front door known as Data Security Posture Management (DSPM) for AI. DSPM for AI continuously discovers AI tools and agents in use, scans underlying data repositories for permissive access rights and missing protection labels, executes automated risk analytics based on user risk profiles (high, medium, or low), and applies real-time policy guardrails. This governance surface extends seamlessly across first-party Microsoft services (Microsoft 365 Copilot, Copilot Studio, Microsoft Copilot in Fabric, and Security Copilot), custom enterprise applications integrated via the Microsoft Purview SDK, and third-party or consumer GenAI services accessed over local networks or web browsers.

Key Architecture Takeaway: Microsoft Purview establishes a unified, continuous control plane across the enterprise data estate. By injecting real-time classification, DLP blocks, Adaptive Protection, and immutable audit logging into the AI grounding lifecycle, Purview prevents sensitive data exfiltration and agent oversharing without disabling GenAI productivity.

3. The AI Grounding Path & Real-Time Control Lifecycle

3.1 Step-by-Step Data Path Sequence

  1. User/Agent Prompt Initiation: An end user or autonomous agent submits a natural language prompt or query into an AI interface (e.g., Microsoft 365 Copilot, a Copilot Studio custom agent, or a custom enterprise LLM application).
  2. Grounding Data Retrieval: The AI application initiates Retrieval-Augmented Generation (RAG) by fetching grounding context from enterprise data stores (SharePoint Online, OneDrive for Business, Microsoft Teams, or OneLake via Fabric mirroring/shortcuts).
  3. Control Gate Evaluation: Before grounding content is passed to the Large Language Model (LLM), Purview's active control gate intercepts the transaction to evaluate security rules concurrently: * Sensitivity Labels & Encryption: Checks if the grounding file contains specific sensitivity labels configured with access restrictions (e.g., "Restrict Access by Label" or site-level exclusions). For example, if a document is labeled with highly confidential protections (such as "Project Obsidian M&A"), Purview prevents the AI engine from reasoning over the file, even if the user invoking the prompt is the document owner. * Data Loss Prevention (DLP): Evaluates whether the prompt content or referenced files match Sensitive Information Types (SITs) or Trainable Classifiers. * Adaptive Protection & Risk Levels: Assesses the user's real-time risk profile (low, medium, high) calculated by Insider Risk Management. If a high-risk user inputs sensitive data, the input is actively blocked; if a low/minor-risk user performs the action, the prompt proceeds but generates an audited activity event with an informational banner. * Access Rights: Verifies standard Entra ID user permissions and site sharing boundaries.
  4. Response Generation or Block Action: * If Allowed: The AI model processes the grounded prompt and emits a generated response back to the user or agent. * If Blocked: The control gate terminates processing over restricted files or blocks sensitive prompt submission, returning a localized policy error (e.g., "Unfortunately, I can't provide detailed information because the content is protected").
  5. Audit Logging (CopilotInteraction Event): Telemetry from the interaction is generated and dispatched to the Microsoft 365 Unified Audit Log under the CopilotInteraction record type. For standard Microsoft services, activity logging is enabled by default.
  6. Downstream Routing & Investigation Surface: The captured CopilotInteraction telemetry is automatically routed across Purview's compliance engines: * DSPM Activity Explorer: Exposes detailed prompt text, response text, and matching SITs for security analytics. * Data Lifecycle Management (DLM): Retains or deletes interaction artifacts according to policies scoped to "Microsoft Copilot Experiences". * eDiscovery & Communication Compliance: Enables legal holds, targeted item class searches, and non-compliant prompt investigations (e.g., unauthorized attempt to retrieve acquisition data).

4. Governance Controls Framework for AI

Purview relies on a trio of active security controls to enforce data protection boundaries across Generative AI workloads.

Sensitivity Labels & Encryption

Sensitivity labels represent persistent metadata markings applied to files and emails that travel with the content wherever it resides. Within AI workloads, Purview sensitivity labels directly regulate how Copilots and agents reason over sensitive information: * Reasoning Restrictions over Protected Content: When a file is protected with a high-stringency sensitivity label (e.g., highly privileged "Project Obsidian M&A" documents), Purview prevents Copilot and autonomous agents from using that document as grounding data. Even if the user invoking the agent is the direct author and owner of the file, the agent's reasoning engine is blocked from accessing or summarizing the document. * Restrict Access by Label Policies: Administrators can configure granular policies that dynamically restrict AI access across specific sensitivity labels without modifying raw user access rights to the underlying site. * Site-Level Exclusions: Entire SharePoint sites containing highly sensitive information can be excluded from AI indexing and agent reasoning, completely hiding site contents from GenAI tool visibility. * Default Labeling for New Artifacts: Site-level default sensitivity label policies can be deployed to automatically enforce protection settings on all newly created documents within a given repository.

Data Loss Prevention (DLP) & Adaptive Protection

Purview DLP policies inspect text inputs, prompts, and file attachments in real time to prevent sensitive data exfiltration into unauthorized AI environments: * Adaptive Protection Integration: Purview dynamically adjusts DLP policy enforcement based on individual user risk profiles calculated by Insider Risk Management (categorized into Low/Minor-risk, Medium-risk, and High-risk tiers). * Differential Risk Enforcement: * Minor-Risk Users: When a minor-risk user pastes sensitive information (such as credit card numbers or internal financial plans) into a GenAI tool like ChatGPT, the system allows the action to complete but issues an on-screen warning notifying the user that their action is being actively audited, simultaneously generating a log in Activity Explorer. * High-Risk Users: When a high-risk user attempts to type or upload sensitive information into an unmanaged consumer GenAI site (e.g., ChatGPT Consumer, DeepSeek, or Google Gemini), Purview's endpoint/browser control actively blocks the prompt submission or file upload at the user interface level. * Deep API Integration for Managed Enterprise AI: For enterprise-grade managed AI workspaces (e.g., registered ChatGPT Enterprise tenants), Purview utilizes direct server-to-server API integrations to audit prompts and capture complete visibility into generated responses. * Security Posture Implications for External Agents: Unmanaged or external autonomous agents—such as those operating natively within unsupported platforms like ChatGPT Enterprise or Claude Enterprise—represent a significant architectural risk. Because Purview Agent Protections currently exclude these runtimes, enterprise users invoking third-party agents against internal data repositories operate in a functional security blind spot where automated classification enforcement and agent-level DLP guardrails cannot be enforced at runtime.

Access Control & Site Oversharing Assessments

Data oversharing—where underlying repository permissions are overly broad—represents a primary vector for AI-driven data leaks. Purview mitigates oversharing through automated posture tracking: * Automated Weekly Oversharing Assessments: DSPM for AI executes an automated 7-day scanning cycle that evaluates the organization's top 100 SharePoint sites by usage. * Risk Identification: The assessment flags sites containing sensitive information that exhibit permissive permissions (e.g., open to "Everyone except external users" or exposed to unauthenticated/anonymous internet users) alongside sites lacking adequate sensitivity label coverage. * Remediation Protocols: From the assessment dashboard, compliance administrators can execute targeted remediation actions, such as enforcing "Restrict Access by Label" policies, applying site-wide sensitivity labels, or completely removing a permissive site from Copilot and agent visibility.

Unified Audit Log (CopilotInteraction) & Telemetry Mechanics

  • Event Generation Mechanics: Every AI prompt and response sequence across supported Microsoft services generates an audit event classified under the record type CopilotInteraction. Activity logging is enabled by default out of the box for M365 Copilot and Azure AI built services.
  • Copilot Studio Thread ID Dynamics & SIEM Integration Risk: For agents built within Copilot Studio, standard Unified Audit Log events capture metadata and the underlying transcript thread ID, but omit raw chat text payloads from the audit record itself. When an investigator views the interaction inside the Purview DSPM for AI portal, Purview dynamically fetches the full conversation text using the thread ID. SIEM Architectural Risk: Security Operations Center (SOC) teams relying solely on raw Unified Audit Log SIEM exports (e.g., streaming into Microsoft Sentinel or Splunk via Management Activity APIs) will receive only thread identifiers rather than plaintext prompts and responses. Reconstructing full agent conversations within external SIEMs requires engineering custom automation playbooks that query the underlying Graph or DSPM APIs using the captured thread ID.

Collection Policies

  • Requirement for Full Text Capture: For specialized workloads—specifically Microsoft Copilot in Fabric, Security Copilot, and non-Copilot enterprise AI applications—prompt and response text are not captured by standard default logging.
  • Impact of Omission: If an explicit Collection Policy is not created and enabled within Purview, the system logs basic high-level audit event metadata only; the actual raw prompt text and model output text are omitted, creating a permanent telemetry blind spot for forensic investigations.

Data Lifecycle Management (DLM) & Retention

  • Target Location Scope: Purview DLM provides dedicated location scoping for GenAI interactions under the administrative location named "Microsoft Copilot Experiences".
  • Policy Execution: Retention and deletion policies applied to this location systematically preserve prompt and response interaction records for specified regulatory durations or execute automated permanent purges when retention periods expire.

eDiscovery & Investigation Workflows

  • Item Class Target Filtering: eDiscovery managers can search, review, and hold AI interaction data across Exchange mailboxes and Teams interaction stores using precise message class attributes. Copilot Studio agent interactions are targeted using specific item classes such as: text IPM.SkypeTeams.Message.Copilot.Studio.*
  • Legal Holds & Review Sets: Placing a user or mailbox on eDiscovery hold automatically preserves all underlying GenAI prompt/response threads. Collected interactions can be added to review sets for full thread rendering, annotation, and legal export.
  • Communication Compliance: Activity signals from AI interactions flow directly into Communication Compliance policies to detect non-compliant behavior, such as users attempting to engineer prompts to extract privileged M&A details, insider trading data, or unethical content.

6. Integration Surface: APIs, SDKs, Connector Frameworks, and Identity

Purview integrates with external clouds, on-premises stores, SaaS apps, and custom development environments via specialized integration surfaces.

6.1 Development Surfaces (APIs & SDKs)

  • Microsoft Graph Purview APIs & Purview SDK: Developers building custom, in-house GenAI applications can integrate with the Purview SDK to route application prompt inputs, model outputs, and user metadata directly to Purview.
  • Know Your Data (KYD) Policy Configuration: To activate custom AI monitoring, administrators create a Microsoft Purview Know Your Data (KYD) policy in the Purview portal. This policy configures the Microsoft Graph APIs to capture custom app calls, analyze payload text using Purview sensitive information classifiers, and display findings within DSPM for AI reports and Activity Explorer.
  • Security & Compliance PowerShell & Authentication Migration: Security and Compliance PowerShell is utilized for administrative policy automation and compliance management. Architectural Impact: eDiscovery PowerShell cmdlets have systematically migrated away from legacy app-only authentication (Exchange Online / Compliance PowerShell sessions). Administrative automation scripts must be re-architected to authenticate via Microsoft Entra app registrations backed by explicit Microsoft Graph API permission scopes (specifically eDiscovery.Read.All and eDiscovery.ReadWrite.All). Legacy scripts failing to update to Graph API authentication will experience operational execution failures.

6.3 Identity Framework

  • Cloud Identity Pairing: Office 365 Commercial and Office 365 GCC environments pair with Microsoft Entra ID in commercial Azure. High-security government clouds (Office 365 GCC High and Office 365 DoD) pair exclusively with Microsoft Entra ID hosted in Azure Government.
  • Microsoft Entra Agent ID: Provides a centralized enterprise directory service that registers, identifies, and catalogues autonomous AI agents created across Copilot Studio and Azure AI Foundry, allowing Purview to map agent identities directly to governance policies.
  • Service Accounts for On-Premises Scanners: The Information Protection Scanner requires an Active Directory service account synced to Entra ID. The account must be granted local Read/Write/Modify permissions over target SMB/NFS file shares (Read-only for discovery mode) and must be explicitly assigned a Microsoft Purview license to execute classification, labeling, and protection actions.
